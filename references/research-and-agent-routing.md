# Agent 编排与联网研究契约

## 能力路由

按下列优先级选择能力；同一字段只保留一个主来源，其他来源用于冲突检查。

| 优先级 | 能力 | 适合任务 | 降级方式 |
|---|---|---|---|
| 1 | 官方旅行 Skill / MCP | 优先 Kiwi 航班搜索、TourMind 机票补充与预订、地理编码、路线规划、天气、酒店、门票、导航与叫车链接 | 官方网页或静态联网研究 |
| 2 | 专业 Agent / Skill | 目的地知识、路线节奏、住宿片区、餐饮、视觉叙事 | 主 Agent 顺序完成同一研究清单 |
| 3 | 联网搜索与网页抓取 | 公开亲访经验、官方公告、开放时间、季节活动、交通规则、公开图片 | 模型已知信息，并明确“可能过时” |
| 4 | 用户资料 | 固定预订、个人经历、照片故事和偏好 | 不可由外部资料覆盖 |

## 专业 Agent 分工

宿主支持多 Agent 时，主 Agent 可按任务需要并行调用边界清楚的研究角色，常见分工包括：

1. **目的地研究 Agent**：天气、季节、开放日、限时活动、当地规则与官方来源。
2. **路线与服务 Agent**：坐标、点到点交通、住宿片区、餐饮、预订项与缓冲时间。
3. **视觉叙事 Agent**：把用户照片、原话和经历映射到天/章节，提出画面节奏；不得虚构私人故事。

每个子 Agent 只返回研究包，不直接操作 JourniOne、不改最终交接稿、不发布链接。主 Agent 负责：

- 解决来源冲突；
- 区分用户事实、官方实时数据、静态研究和推断；
- 删除无来源或与用户要求冲突的内容；
- 形成唯一版本的旅程真值。

宿主没有多 Agent 能力时，主 Agent 按同样三个角色顺序研究，产出格式不变。

## 必查内容

按 [分步规划](../playbooks/progressive-planning.md) 的当前阶段选择，以下是完整确认稿所需资料的候选清单，不是首个可见结果的前置门槛。兴趣探索可先轻量核验一两个真实选项，按 [兴趣模块](../playbooks/interest-discovery.md) 直接呈现；玩法确定后显示骨架与首批建议时间线，再补齐全程并核验正式采用的具体体验，最后汇总地图；不为凑字段添加无关信息：

- POI 坐标、开放时间、休息日、参考门票和预约窗口；
- 相邻节点的交通方式、耗时、换乘和缓冲；
- 跨城、机场、港口、换酒店、取行李和末班风险等关键接驳；在活动与餐饮研究同批执行，给出当前行程主选、必要时的条件式备选及运营方官网；
- 出发月份的天气、极端天气与穿搭；
- 时令活动及明确起止日期；规划未来行程时，每个行程段补充 1–3 个能服务主题或替代风险的活动灵感；
- 与每日区域和节奏匹配的餐饮选择；当前展开天次每个非例外用餐或喝东西时段落实一个可检索的具名店铺，按需留少量备选；按 [活动与餐饮落点](activity-classification-contract.md#具体日程的活动与餐饮落点) 区别纯休息事件与餐饮，不用固定候选上限导致漏餐次；
- 用户已选择酒店推荐时，研究与路线地理分布匹配的住宿片区、晚数与入住配置；先比较 2–3 个区域并给出一个主选，再按 [accommodation-area-and-hotel-handoff.md](accommodation-area-and-hotel-handoff.md) 形成 TourMind 住宿搜索包，不用网页研究编造具体酒店或实时价格；
- 只有用户选择补航班时，按 [flight-booking-routing.md](flight-booking-routing.md) 优先使用已就绪 Kiwi 搜索与首末日匹配的航班，Kiwi 未就绪时使用 TourMind 机票补充，用户明确指定供应商时遵从其选择；预订链接仅使用实际返回值，并把抵离机场写回路线；已预订航班不主动替换；
- 需要提前预订的事项与建议提前天数；
- 用户图片优先，公开图片仅作补充，并验证 URL 可加载与使用条件。

活动与餐饮候选遵循“先发现、后核实”，并以已有目的地、住宿片区、主锚点和已知旅行日期为搜索边界。日期未知时近期活动仅作注明实际日期的灵感，不先索取日期，也不把样本写成出行期间已确定场次。只有聚合页、搜索摘要或旧届资料支持时只能标为灵感参考；无法核实路网时不能把地图直线距离写成步行时间。简版流程见 [nearby-activity-and-dining.md](nearby-activity-and-dining.md)。

关键交通先用官方路线工具或可靠路线结果判断可行性，再用运营方官网核实线路、车站、时刻表与运行状态。运营方普通网页可以作为 `operatorUrl`、`timetableUrl` 或 `statusUrl`，但不等于实时票价或可订状态；购票、预约和导航 `actionLink` 仍只接受官方工具原样返回值。简版流程见 [critical-transfer-search.md](critical-transfer-search.md)。

## 来源与时效规则

- 按主张选来源：体验适配优先找有情境的亲访记录；营业、位置、预约等运营事实优先用商家、主办方或运营方资料。只查营业或交通时无需额外搜体验文章。
- 采用经验时，在现有研究包的结论与适用范围中简记谁、哪个分店、何时及什么条件下的感受，以及它为何影响当前选点、顺序、停留方式或备选。区分亲历、转述、推广与自己的推断；未知条件不补猜，发布时间不等于到访时间，“雨天安静”不泛化成始终安静。保留实际影响取舍的反例；感受冲突先看情境，关键营业冲突优先核对最新一手信息，未解则留待核实。
- 只使用实际读到的内容：搜索摘要用于发现，局部正文只能支持可见部分，不声称已读全文。转载、翻译和同文跨站不算独立佐证。沿用来源 URL、核验时间和待核实记录，按需注明阅读缺口；不新增必填表格或接口字段。
- 本项经验研究只用宿主已有搜索和公开网页读取。登录、付费、验证码或读取失败时换可读来源；不凭工具报错猜原因，不为解锁内容增加 API、插件、Cookie 或浏览器自动化。找不到可读经验时说明缺口，用可核实资料继续；联网不可用时提供待核实方向，不阻塞规划。
- 区分“一手运营事实”与“商业营销结论”。航司、酒店、餐厅、景点、活动主办方、票务商和交通运营商的官网适合确认其自身时刻、位置、菜单、设施、库存、价格、限制和取消规则；其“最快、最省、最佳、最受欢迎、正宗、超值、必去、适合所有人”等自我评价不作为客观比较证据。
- 采用任何比较性主张前，核对主张的端点、日期、比较基准、人数、车辆、房型、票种、包含费用和限制是否覆盖当前行程。只有范围一致，并有官方路线工具、公开数据或独立来源支持时，才能写成中性结论；否则明确归因为“运营方称”、降为体验线索或直接省略。
- 不把局部服务优势外推到完整旅程。例如某段轮渡航程短，不代表出发住宿到最终目的地更快；某酒店宣称靠近景点，不代表从当前抵离车站或每日主线最顺路；某餐厅或活动自称“当地最佳”，不代表适合用户日期、预算和路线。
- 广告、赞助与联盟推介不得单独支撑排名、性价比或主选结论；但网页带有联盟链接，不等于整篇亲访记录不可用。按具体段落判断：可辨认的亲历细节可支持有归属、有情境的体验说明，商业推荐另行看待，不把作者的“最佳”变成客观结论。
- 技术事实和可验证信息不只引用搜索结果摘要；打开原页面确认。
- 所有网页研究在内部记录 URL 与核验日期；对用户保留来源链接、实际适用日期和影响决策的限制。按 [口语化表达](onboarding-contract.md#口语化表达与有效选择) 自然说明“定了哪周去再找对应场次”等下一步，不把核验元数据复制为兴趣推荐尾注；正式路书中需要复核的事项仍保留。
- 普通网页不提供可靠实时票价。航班、酒店、门票实时价格只采用已授权官方工具返回数据；供应商航班价格与实际返回链接记录核验时间，用户尚未选择时标记“建议航班待确认”。
- 活动排期与餐饮营业规则优先主办方、场地方、官方菜单、订位页和官方社交账号；地方媒体、个人博客与公开社区可支持与用户偏好相关的具体体验判断，不能替代当前营业与可订状态核验。没有官网的小店可保留为待核实候选，关键条件未知时不写成已落实的固定安排。
- 官方工具数据的时效与真实性由对应工具负责；JourniOne 只编排和展示，措辞保持中性。
- 行动链接只用官方工具返回值，不手拼预订、导航或叫车 deeplink / URL scheme。
- `mapUrl` 不是 `actionLink`：主 Agent 可以把已核验的 WGS-84 坐标按行程顺序确定性拼成 `https://www.google.com/maps/dir/{lat},{lng}/...`，并连同节点 `lat`、`lng` 回传 JourniOne；不得用名称猜坐标，也不得改写官方工具返回的行动链接。
- 高德与腾讯通常返回 GCJ-02；用于 OSM/WGS-84 地图前必须转换。
- 外部研究不得覆盖用户确认的预订、经历、原话或隐私选择；发现冲突时向用户说明。

## 研究完成门槛

进入 JourniOne 前确认：

- 每一天/章节的主要节点都有明确安排依据；
- 关键交通与时间约束不存在明显冲突；
- 高风险易变信息均有来源与核验日期；
- 推断项和待核实项没有伪装成事实；
- 本轮涉及体验优化时，已采用的经验能在对外建议中找到对应的保留、调整或放弃理由及原文链接；只有运营核验时不宣称已补充亲访经验。来源缺口不阻塞已有可行路线，不为通过检查凑数量；
- 所有外部 Agent 结果已经合并进同一份旅程真值。
