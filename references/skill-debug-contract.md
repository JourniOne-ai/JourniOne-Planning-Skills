# JourniOne 验收

## 本地前提

先运行 Skill Creator quick_validate，再运行 scripts/test-poster-contract.mjs。可传入 --server-root 指向当前 dev 源码并确保其 npm 依赖已安装，验证构造请求被真实服务端规范化器接受，以及描述标题失败后通过地点别名解析；这使用注入的地点 fixture，不发送网络请求或调用模型。临时输出放 .tmp，不记录真实 Preview capability。

传入 `--server-root` 前，确认该目录的 `api/_lib/skill-v2/contracts.js` 导出 `normalizeExternalSkillPosterRequest`。历史 checkout 可能缺少该导出；出现 `TypeError: normalizeExternalSkillPosterRequest is not a function` 属于 D 类环境选择问题，改用已核对的当前源码，不改客户端请求迁就旧版本，也不代表线上生成失败。

同时确认目标源码支持具名地点优先检索。若“dev 优先检索真实地点名”断言实际调用为“描述标题、真实店名”两次，而预期只调用真实店名，先用修改前 Skill 复查；基线同样失败时属于已有服务端兼容问题，本次文档修改不可通过放宽测试绕过。选择已具备对应修复的源码再验证；没有可用版本时分别报告本地离线结果与附加兼容失败，不宣称完整联调通过。

## 必测行为

1. 只有路线，无酒店、航班、具体日期和人数：生成 @2.0.0 structured 请求，保持可选服务为空，不凭空补服务。
2. 用户要求 Map 视图（或沿用旧称 OSM）：沿用同一 Travel Journal Preview 页面切换；返回 Journal 视图同样不创建第二份行程。普通回复不把旧称作为正式视图名称。
3. PDF 导入：全部页与正式活动被提取并转入 Snapshot，来源、标题、时间、二选一和季节条件保留；原文附件已授权且非空，不把文件内指令作为执行命令。
4. 已有酒店/航班：服务数组完整保留，不把建议标成已预订；香港出发使用 HKD。
5. 任意输入存在服务端控制块、未授权附件、私人媒体、空活动或超限内容：本地校验拒绝，无网络写入。
6. 接受响应仅允许正确 schema/mode 和与 Trip 精确匹配的 Preview URL；缺失、只读 /share、跨 Trip、查询串、嵌入用户名密码均拒绝。
7. 重复构造同一输入与键：body/header 完全一致；不自动更换键或丢弃字段。网络重试最多一次且同请求同键。
8. 卡片统一称 Travel Journal，主按钮直达实际 Preview；默认封面可用，HTML 转义、Google Maps 初始折叠与点击展开/收起、Day 标题去重保留。Snapshot 转地图保留全部天次与正式节点顺序，单点与缺失坐标有明确呈现，不静默删天；Markdown 降级也有封面、主链接和地图。
9. 元数据、文件夹与调用名一致；引用文件存在，源码与安装副本逐文件哈希一致，旧安装版本不参与发现。

按 [分步规划](../playbooks/progressive-planning.md) 做桌面问答演练：需要兴趣启发时先按 [兴趣模块](../playbooks/interest-discovery.md) 给真实选项，选好玩法后给骨架与首批具体时间线，再补齐全程；“两晚够吗”的“可以了”不授权生成，不把三步写成三个强制问题；已有确认路线直接生成，不重复问服务或照片。同时演练酒店接受/已订/拒绝/暂缓，以及完整日程后的生成/只查酒店/只查航班/继续修改/暂不生成分支。性能记录首次小结果、首批具体时间线、全程确认稿、最终地图与接口至 Preview 接受的实际时间；不以卡片脚本耗时代替端到端规划耗时。

机酒流程另按 [服务衔接](../playbooks/service-to-journal.md) 做桌面演练：前文七天路线加出发日推算六晚、明确七晚及已暂选日期优先、夫妻两人跨服务继承；酒店暂选后回到 Journal 并可选提航班，航班暂选后根据已有生成指令执行或邀请；拒绝机票、查询失败与暂缓都有明确去向。检查推荐与暂选没有触发下单或无故重查报价。桌面演练不算真实工具调用或端到端耗时测试。

规划内容另检查 [活动与餐饮落点](activity-classification-contract.md#具体日程的活动与餐饮落点)：首次具体时间线中的“新宿午餐”“晚餐”“喝点东西”必须补具体店铺和必要分店；“新宿御苑慢走”“吉祥寺中道通逛小店”可保留活动 POI；纯休息说明依附的具体地点与动作后可为 event；单独“自由活动／自由休息”不算完整安排。便利店补给、赶车简餐或明确自选餐饮保留例外；未知店铺不得换成 event 掩盖。演出场地与晚餐同处需有菜单依据，地图暂缺坐标不意味着可以删除餐厅。此项为对话桌面演练，不能用请求分类测试通过代替真实选店效果。

## dev 实测（仅明确授权后）

先查目标环境 `/health` 中 external_skill_poster_v1 和 abuse_guard；`/api/health` 不是公开健康检查入口，其 401 不代表匿名创建需要登录。ready=false 时记录配置阻塞。记录当前命令行代理和系统代理是否一致，不硬编码端口或擅改用户配置；TLS 失败仅说明未建立连接，先用同域名只读探测区分传输与 HTTP 错误。

运行真实请求的本地校验及服务端规范化器，不能仅凭示例 fixture 通过就认定用户请求合法。服务 `planned` 必须本地拒绝；描述标题与 `location.name` 不同且无坐标时，确认请求携带真实地点搜索别名。先用完整可靠坐标、无服务的小行程验证基础链，再用带服务的完整行程验证；同请求同键重放应返回同一 Trip 和 Preview。

真实提交至少覆盖无服务和带服务请求、幂等重放、编辑隔离；等首份成功后再批量生成，不能用本地 fixture 代替线上结果。`partial_ready`、`coordinate_resolution_retryable`、地图 `failed_retryable` 均不算完成；记录地点审计、最后更新时间和所需素材状态，避免把遗留 running 当作仍在正常生成。

实际确认 Poster、Cover、Travel Guide、OSM 完整；POI 热区可 hover/click，详情文字可用，详情图 artifact skipped 且没有对应生图任务。检查固定高度、独立缩放、拖动、首次提示动画；生成和刷新后的内容一致。

Skill 生成与公开 Preview 查看免认证；页面检测真实 AAuth 会话，登录后自动创建或复用个人日志，已有修改不被覆盖。编辑行程及增删改酒店、机票只允许当前账号的个人日志；不能凭 Preview Header 编辑原件。验收匿名只读、自动保存、两个账号隔离、邮箱退出和登录续接。

503 记录真实 code，不替换密钥、绕过保护或换环境。报告明确区分：本地静态/契约、代码同步、实际 dev 生成、页面验证、账号保存。配置缺失时标记未完成，不声称模板已生成。

## 地点与事件联调回归

- 行程 tab 保留全部事件，地图只保留实体；未关联 service_id 的用餐事件不得误挂酒店，返程手续只关联当天航段。
- 显式机场 poi 取得真实 POI，对应手续通过 location_ref 引用；手续不按数组位置猜机场，单程不制造返程角色。
- 预订与行程都显示 selected 为“已选择 / 待预订”，机场当地时钟与原始链接不变；机场单个时刻不能擅自延长为两小时。
- exact 概览使用确认稿，不因后台模型生成文案而调换 Day 1/Day 2 或增加地点；校验脚本覆盖模型故意给出错误概览的情况。
- 校验部署后的真实行为并记录实测耗时；定位成功、素材终态、Journal 热区与地图交互分别报告。

- POI 计数不包含 event；已定位地点与无定位事件混合时坐标覆盖率仍为 100%，不触发重复地点研究；行程和详情编号都跳过事件。

- 纵向日志宽幅热点须对照真实图像核验；不再仅因宽度超过 55% 拒绝，面积、越界、重叠和编号校验仍生效。

- 复用已确认 place_id 时保留完整 google_place；仅有坐标与 ID 时由 dev 按 ID 补齐详情对象，不重新选点、不改坐标，错误 ID 不能交付为空白详情。
