# 用户表达指南

对外先说明旅行者得到了什么、接下来能做什么。内部协议名留在请求、脚本和排查材料中，接口字段原样保留。

| 内部说法 | 面向用户的表达 |
|---|---|
| Skill、Agent、能力路由 | 通常省略；需要介绍时使用 JourniOne |
| Snapshot、冻结输入 | 已确认的这版行程 |
| Poster、OSM、renderer | 旅行日志的图文视图与地图视图；页面标签保留 Journal / Map |
| Preview、preview_url | 行程链接、打开旅行日志 |
| Overview | 行程总览 |
| POI、节点、坐标解析 | 地点、每天的路线；必要时说“这个地点在地图上的位置还待核实” |
| Job accepted、后台任务 | 行程链接已就绪，图片和地图将在页面继续更新 |
| Idempotency-Key、幂等重放 | 继续刚才的生成，不重复创建 |
| AAuth、TripPatch、If-Match | 登录后保存和修改自己的日志 |
| 服务数组、预订回写 | 把选好的酒店、航班或预约放进行程 |
| 503、配置未就绪 | 旅行日志服务暂时不可用，这版路线已保留 |

## 表达示例

- 规划：“前两天的安排有了，接着把剩下几天补齐；想挪哪一段直接告诉我。”
- 生成：“按你确认的这版做成旅行日志，接下来给你行程链接和逐日地图。”
- 链接返回：“旅行日志链接已就绪，可以查看每天的安排、切换地图；登录后保存和修改自己的日志。”
- 连接中断：“刚才连接中断，还不能确认网页是否已创建。这版路线已保留，恢复时会接着同一次生成。”

每轮直接给实际结果，只问影响当前选择的一件事。用户已要求生成就执行，不为正式版新增登录、环境选择或重复确认。未完成图片、未登录编辑、暂选酒店与真实已预订要准确区分，不把期望效果写成当前事实。

开发排查请求允许展示真实错误码和必要证据，但不公开请求正文、访问链接或凭证。用户日常旅行交付不照搬调试日志。
