# Travel Journal 交付

Travel Journal 是把已确认路线整理成的可分享图文网页，方便和同行人一起看每天怎么玩；日期、机票和酒店可以按需求持续补充。首次交付为免登录只读的 Preview；已登录打开自动创建或复用个人日志，只有账号本人能编辑。个人修改需要对外分享时，在页面另建只读链接。

## 首次交付

用户已看过完整具体日程并选择生成后，提交完整结构化行程并取得符合 [trip-snapshot-contract.md](trip-snapshot-contract.md) 的响应。唯一主链接是接口实际返回的 preview_url，路径 /preview/<trip_id>，用户登录后可在个人日志中编辑。酒店、航班、日期或人数缺失不构成 Travel Journal 生成门槛。

Preview 已返回不等于图片已生成完成：正常交付立即给链接，异步视觉由页面展示，不等待封面、POI 图片、预订库存或打开页面验收。用户明确要求测试时，另行检查图片和可编辑性，不把链接接受当作验收通过。

交付时按 [阶段引导](onboarding-contract.md#每个阶段的一句话引导) 用一句话收口并说明如何使用：“旅行日志链接已就绪，可以查看每天的安排、切换地图；登录后保存为自己的日志再修改，也能从页面分享给同行人。”随后给实际行程卡与地图；素材尚未完成时如实补充状态，不说整份成品已经完成。用户只要链接时省略额外介绍。

## 卡片与完整正文

默认必须返回行程卡与 Google Maps，不把它们视为可选附件。宿主支持对话内可视化时，使用 [roadbook-card-rendering.md](roadbook-card-rendering.md) 的确定性脚本；没有即时成图就用自带封面。宿主不支持或脚本失败一次时，立即使用完整 Markdown 卡片，保留封面、日期/目的地、标题、简介、标签、Preview 主链接及逐日地图，不能只留下裸链接。主按钮统一“打开 Travel Journal”，主链接在卡片内出现一次。

以同一冻结 Snapshot 的全部正式节点为输入；已有 WGS-84 坐标先生成单点 Google Maps 与逐日路线。每个天次都要呈现：至少两个有效点给路线，一个点给单点地图，没有有效坐标时保留当天标题并写“地图待核实”。部分点缺失时显示尚未包含的点名，不伪称地图完整，也不删除正文或 Snapshot 中的正式点位。生成前按分步规划完成必要核验，不等网页生图再做地图。

链接后依次提供：
- 行程 Overview：完整横向总览；
- 最终行程：全部正式节点及简洁时间线；
- 出发前需要确认：尚未预订或必须复核的条件，没有时写“无”；
- Tips：与本次同行者相关的提醒。

用户明确只要链接时遵从；否则即使正文已交付，行程卡与逐日地图仍须返回，长文可依用户要求简化。展示规则延续 [itinerary-presentation.md](itinerary-presentation.md)，服务状态、来源和币种不得丢失。

酒店/机票仍适用且此前从未询问时，在交付后可轻问一次；此前已拒绝、暂缓、已订或选择先生成时不重复邀请，切换 Journal 视图或 Map 视图不需要先补服务或重新生成。

## 权限

Preview 是公开只读入口，不是编辑凭证。已登录访问时自动创建或复用个人日志，无需再点保存；未登录点击「保存为我的日志」或编辑、添加机酒后，通过现有 AAuth 登录并自动继续原操作。顶部显示账号邮箱并支持退出。同账号同来源只有一份副本，原件不变。/share/<snapshot_id> 继续是独立只读快照。

## 失败

没有有效 preview_url 就不能宣称路书已生成，不能从 ID 拼接、拿其他 URL 字段替代或另画图片。保留冻结请求；超时同键有限重试，503 配置错误停止，429 遵守服务端提示，具体错误处理见请求契约。向普通旅行用户简短说明当前尚未生成；面向开发排查如实给错误与证据。

封面尚未准备好时用随 Skill 发布的默认封面，不把默认封面当作实际生成验收。预订请求单独按 [post-delivery-booking.md](post-delivery-booking.md) 授权。
