# Kiwi.com 可选航班与机场契约

本文件适用于默认普通航班推荐所复用的已就绪 Kiwi，以及用户明确选择 Kiwi 公开搜索或跨供应商比较的情况。预订依赖与供应商路由见 [flight-booking-routing.md](flight-booking-routing.md)；本文件的免登录、单主选、缓存与 `bookingUrl` 规则不能套用到 TourMind。

这套流程用于路线结构已经确认、未来旅行仍需明确往返或单程航班的阶段。目标是让首轮规划不被航班输入阻塞，再让真实航班约束首末日、住宿与机场接驳，并把 Kiwi.com 原样返回的 `bookingUrl` 交给用户；不代替用户下单。

查询、给首选、暂选和失败都按 [机酒补充与 Journal 衔接](../playbooks/service-to-journal.md) 接回当前路线与 Journal。进入航班工具不清空已有酒店、人数、日期或“选完就生成”的要求。

## 触发判断

- 用户明确说“已订、出票、这是我的航班”时，不搜索替代航班；记录航班号、日期、机场和当地时间。
- 用户尚未确认目的地、天数分配和逐日主线时，先完成路线草案，不为航班询问日期、人数或偏好，也不为每个灵感目的地批量搜索航班。
- 用户明确要求航班，或在完整日程后选择先看航班时进入推荐流程；只同意酒店推荐不授权航班查询，交通信息会影响路线也不构成自动查询授权。
- 用户同时选择酒店与航班时，两项属于同一补全批次；只选择一项则仅处理该项。以下联动仅适用于两项均已授权：用户用一句话补全日期、出发地或同行人数后，必须同时重算酒店与航班搜索指纹；若 `flyFrom`、`flyTo`、去回日期和人数年龄分组均已存在于旅程真值，直接搜索并提供往返航班首选，不再单独询问是否需要机票，也不得因酒店查询已完成、失败或尚未下单而省略。
- 用户已选择航班推荐且仍缺具体日期时，此时才询问日期；仍缺实际人数年龄分组或出发地时，把搜索必需项合并为一次提问。
- 用户明确表示航班已订、不乘飞机或不需要机票时不搜索替代航班；不得仅从“用户没有主动提机票”推断其不需要航班。

## 工具与身份边界

- 远程 MCP 名称：`kiwi-com-flight-search`。
- Streamable HTTP 端点：`https://mcp.kiwi.com`。
- 航班工具：`search-flight`；不要误写为 `search_flights`。
- `search-flight` 是公开免登录查询，不要求插件安装、账户连接、API Key、OAuth 或个人凭证。
- 只调用只读的 `search-flight`。`feedback-to-devs` 不是航班搜索或失败兜底工具，除非用户明确要求向 Kiwi.com 开发者发送反馈，否则不得调用。

## 输入补全

只在上述推荐流程已经触发后补齐以下搜索输入。先按 [输入继承与估算](intake-contract.md#机酒输入的继承与估算) 读取前文与酒店阶段的同行人数、日期、暂估口径和已知行李；已选酒店退房日可作为暂估离境日，交通未定时不冒充实际返程。只有无法继承或推导的必需项才问，不重新盘问已确认路线或添加舱等、航司等非必要问题。必要提问说明答案会如何衔接首末日与 Journal：

- `flyFrom`：用户给出的出发机场、城市或机场名称；缺失时只追问，不得用 IP、语言、时区或模型记忆猜测；
- `flyTo`：与路线最匹配的抵达城市、机场或机场名称；
- `departureDate`，以及往返时的 `returnDate`，均使用 `dd/mm/yyyy`；
- `adults`、`children`、`infants`：使用本次同行者实际年龄分组；不得把总人数全部默认成成人；
- `currency`：使用旅程统一展示币种；
- `locale`：使用用户当前输出语言对应的 locale，例如繁体中文香港用 `zh-HK`、简体中文用 `zh-CN`、英文用 `en`；
- 用户明确表达时再传舱等、航空公司、经停、时段、行李和灵活日期等约束。

## Kiwi.com 调用

往返两端不对称时，按已确认航段分别查单程，例如香港→悉尼、墨尔本→香港；不能套成香港↔悉尼往返，也不因开口行程跳过 Kiwi。保留用户指定航司为 `select_airlines` 条件（国泰为 `CX`），继承真实人数与日期；两张单程的组合金额不冒充同一往返票价，缺失的一段单独报告。

直接调用免登录 `search-flight`：

```text
flyFrom:
flyTo:
departureDate: DD/MM/YYYY
returnDate: DD/MM/YYYY | 空
departureDateFlexDays: 仅用户允许日期浮动时
returnDateFlexDays: 仅用户允许日期浮动时
adults:
children:
infants:
cabinClass: M | W | C | F，仅用户明确时
currency:
locale:
max_sector_stopovers: 仅用户明确直飞或最多中转次数时
select_airlines: 仅用户明确指定时，逗号分隔 IATA 代码
exclude_airlines: 仅用户明确排除时，不能与 select_airlines 同时使用
adults_hold_bags / adults_hand_bags: 已知行李需求时按每位成人传数组
children_hold_bags / children_hand_bags: 已知行李需求时按每位儿童传数组
allow_self_transfer: 对带托运行李、儿童、长者、滑雪装备或关键衔接默认 false；其他情况只有准备采用自助中转方案时才设 true 并明确风险
allow_overnight_stopovers: 只有用户接受过夜中转时设 true
allow_diff_airport_connection: 只有用户接受同城换机场时设 true
sort: quality
```

未表达的舱等、航司、价格上限、起降时段和灵活日期不要擅自添加。若用户明确只看最低价，可把 `sort` 改为 `price`；明确只看最短耗时可改为 `duration`。

保留工具返回的：

- `query`、`currency`、`passengers`、`resultsCount` 与 `searchTimeMs`；
- 每个 itinerary 的 `price`、`priceFormatted`、`totalDurationSeconds`、`bookingUrl` 与 `baggage`；
- `outbound` 和 `inbound` 的当地时间、经停、路线、舱等与全部 `segments`；
- 每段的机场代码与名称、城市、航空公司、航班号和当地时间。

字段缺失时留空，不从航班号反推。`bookingUrl` 是唯一预订入口，必须原样展示，不手拼、不改写、不加跟踪参数、不用航司首页替代。`price` / `priceFormatted` 按本次 passengers 查询的总价展示；只有明确标注“人均参考”时才允许计算平均值，不能把总价误写成人均价。

## 选择、缓存与展示

把用户明确要求作为硬约束；其余按以下顺序在内部选择最多 3 个差异明显的方案：

1. 符合期望抵达与返程时段；
2. 不含自助中转、同城换机场或过夜中转；
3. 直飞或更少中转；
4. 总时长和首末日可用时间；
5. 行李是否覆盖实际需要；
6. 当前总价。

只向用户展示排名第一的主选，其余方案保存在当前任务的 `hidden_alternatives` 中。首次回复使用单行紧凑表格：

```markdown
### 建议往返航班｜待确认

| 航空公司 | 路线与机场 | 当地时间 | 经停 / 时长 | 行李 | 当前总价 | 预订 |
|---|---|---|---|---|---:|---|
| <航司> | <ORIGIN → DEST> | <起飞 → 抵达> | <经停 / 时长> | <随身 / 托运> | <币种 金额，人数口径> | [查看并预订](<Kiwi.com 原样 bookingUrl>) |
```

表格后只解释主选最重要的两点，例如抵达时间更适合休息、返程与最后一天退房衔接更稳。不要重复每个单元格。

先展示航班对首末日的实际影响，再把选择接到主流程，例如“这组时间能接上已选酒店；可以先放进行程，接着把每天安排做成 Travel Journal”。用户暂选后保存“已暂选未出票”，直接按服务衔接流程继续，不重新复述完整表格，也不只回复“尚未出票或锁价”。

不要主动提示或列出“省钱方案”“最快方案”等第二选择。缓存内容至少包括路线、时间、经停、时长、行李、总价、人数口径、原样 `bookingUrl`、排序理由和核验时间。用户追问“其他航班、便宜一点、早一点、晚一点”时，优先从未失效缓存中返回最匹配的一项；条件变化或报价过期时重新搜索。

```yaml
flight_result_cache:
  provider: kiwi.com
  search_fingerprint: <路线、日期、人数年龄分组、币种、舱等与硬约束>
  verified_at: <时间与时区>
  primary: <已展示主选>
  hidden_alternatives:
    - rank: 2
      itinerary: <航段与当地时间>
      baggage: <包含行李>
      total_price: <金额、币种与人数口径>
      booking_url: <Kiwi.com 原样 bookingUrl>
      reason: <仅内部>
  status: current | quote_stale | invalid
```

## 写入旅程真值

```text
航班状态：已预订 | 已暂选未出票 | 建议航班待确认 | 待搜索 | 工具未连接
供应商：Kiwi.com
出发：日期 / 出发机场代码与名称 / 当地起飞时间
抵达：抵达机场代码与名称 / 当地抵达时间
返程：日期 / 离境机场代码与名称 / 当地起飞时间 / 抵达机场
人数：成人 / 儿童 / 婴儿
行李：随身 / 登机箱 / 托运行李
Kiwi.com 预订链接：原样 bookingUrl
核验时间：
价格状态：当前搜索总价，重新搜索前不保证
```

Day 1 第一段写“前往出发机场”或从出发机场起飞，抵达段写明确机场和进城接驳；最后一天写退房、前往离境机场和起飞。用户尚未选择航班时在时间线上标记“建议 / 待确认”，不把建议价格写进正式固定事实。

机场作为交通节点可以进入行程和 JourniOne；只有具备已核验 WGS-84 坐标时才进入 Google Maps 路线。航班链接是 `actionLink`，不得当作 `mapUrl`。

## 变化与失效

日期、人数或年龄分组、出发地、目的地、币种、舱等、直飞要求、行李需求或首末日固定活动变化时重新搜索，旧航班价格和链接标记失效。机场变化时同步更新：

- 首末日时间线与 Google Maps；
- 机场接驳和缓冲；
- 第一晚与最后一晚住宿区域判断；
- JourniOne 旅程真值。

## 失败处理

- 初始化已尽可能自动准备 Kiwi，但当前仍缺失、安装未完成或待加载：按 [航班路由](flight-booking-routing.md) 使用 TourMind `flight-booking-ai` 补充，继承已授权查询条件并说明来源，不要求安装 Kiwi，不增加供应商选择确认；TourMind 缺 Token 时进入其授权流程。已有配置但未加载时如实记录加载状态，不误报未安装。
- `search-flight` 查询或传输报错：记录具体查询状态并允许继续规划不依赖航班价格的路线；不改用模型记忆伪造航班，也不索取个人凭证绕过。
- 航班与酒店联动查询时，两项只读查询独立完成；航班失败不撤销真实酒店首选，酒店失败也不阻止真实航班首选。对外分别说明状态，不用一项失败解释另一项缺失。
- 无结果：回显日期、路线、人数年龄分组与硬约束；只提出一个最小放宽建议，不自动改变日期、机场或中转要求。
- 结果缺 `bookingUrl`：可以展示航班灵感，但明确没有可用预订入口；不得手拼。
- 结果含自助中转、同城换机场或过夜中转：只有在用户明确接受风险后才可作为主选，并在展示中直接标明。
