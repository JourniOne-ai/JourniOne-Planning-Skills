# Playbook: 对比 Booking Skills 航班与 Kiwi MCP

## 目的

用同一组只读案例明确 TourMind 与 Kiwi 的请求、认证、响应和后续预订能力差异，并区分源码契约与真实接口证据。

## 前提条件

- 用户明确要求航班能力测试或供应商对比，不等于授权订票或付款。
- 已读取官方两个 Skill 与机票参数指南，记录来源提交和版本；已发现 Kiwi `search-flight` 的当前 schema。
- 测试案例含出发/到达机场、未来日期、用户时区、成人/儿童/婴儿人数、舱等与直飞偏好；对开发测试明确这是样例而非用户的真实旅行。
- Python 3.9+、HTTPS 与临时输出目录可用。TourMind 搜索凭证只允许来自机票目录及相邻酒店目录；缺失则跳过受保护请求。

## 步骤

1. 在 `.tmp/` 写入案例 JSON，每项含 `name`、`operation`、`request`；只允许 `search_airports` 与 `search_flights`，保留准确请求但不写凭证。先做官方版本检查，不将版本接口返回当成航班认证成功。
2. `python3 scripts/probe-flight-search.py --cases <案例文件> --output <不存在的结果文件> --skill-dir <已确认机票目录> --timezone <用户时区>` — 先运行机场案例，核对返回地点；确认代码和请求后再单独运行航班案例。没有凭证记录跳过，不发送空凭证探测。
3. 用当前宿主 Kiwi `search-flight` 对等查询，保存请求、结构化响应和工具错误到 `.tmp/`。不调用反馈工具，不发送消息给供应商。
4. 比较机场、日期、人数、舱等、行李、原币总价、时间和链接。脱敏证据留在本地；报告仅呈现能力、请求与必要的结果摘要。
5. 运行 `python3 -m unittest discover -s tests -v` 检查探测器输入边界，以及 `node scripts/test-poster-contract.mjs` 检查 Journal 契约。测试案例未下单，订单/支付能力只能列为文档声明。

## 判断标准

- 无 Token → TourMind 公共机场照常测试，航班标记未执行，继续 Kiwi 和静态对比。不能判为 TourMind 无票或不可用。
- HTTP 200 但 TourMind `code != 0` → 业务失败。`20105` 是企业预订权限限制，不删凭证、不自动换通道；其他认证失败停止受保护测试，按官方恢复流程处理。
- 空报价 → 正常零结果，不改日期、机场或人数自动重试；接口失败与零结果分别保留。
- 某供应商无法设置币种/行李等字段 → 如实记录差异；结果不等价时不计算“谁更便宜”。
- 受保护请求失败 → 探测器停止后续受保护案例；原始诊断先脱敏保存，不在公开报告打印。恢复或重试需重新确认前提和授权。
- 本流程不验证真实下单或支付；不能为测试凭证创建订单，不采集测试乘客证件。

## 验证

- 官方版本与提交、精确测试请求、实际执行/跳过状态、时间、业务成功码均可追溯。
- 两者的报价、链接、凭证和会话互不替代；全部公开文档不含凭证或旅客资料。
- 明确区分已通过的机场/搜索测试与尚未测试的验价/订单/支付能力。
